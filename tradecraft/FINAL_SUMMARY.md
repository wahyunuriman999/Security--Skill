## Detailed Findings

### 1. OAuth State Reuse — HIGH (Primary Finding)
**Asset**: `shopify.okta.com/oauth2/v1/authorize` (used by `vault.shopify.com`)
**CVSS 3.1**: 7.1 (High) - AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:N

**Root Cause**: Okta authorization server accepts the same `state` parameter value across multiple authorization requests with different `nonce` values, instead of rejecting previously used state values.

**Impact**: CSRF on OAuth 2.0 flow → Account takeover of Shopify employees/partners
- Attacker forces victim to initiate OAuth with known `state`
- Victim completes authorization
- Attacker can complete flow with victim's credentials
- Full access to Shopify partner/employee resources

**Report**: `REPORT_okta_state_reuse.md`

### 2. Storefront API CORS — INFORMATIONAL
**Asset**: `*.myshopify.com/api/2024-01/graphql.json`
**Finding**: `Access-Control-Allow-Origin: *` on all origins, but `Access-Control-Allow-Credentials` is **NOT** set
**Verdict**: **Not vulnerable** - wildcard without credentials is safe for public API

### 3. GraphQL Introspection — LOW
**Asset**: `test-store.myshopify.com/api/*/graphql.json` (6 versions: 2024-01, 2023-10, 2023-07, 2023-04, 2022-10, unstable)
**Finding**: Full introspection enabled on all API versions
**Impact**: Information disclosure - schema enumeration

### 4. GraphQL Alias Overloading — LOW
**Asset**: `test-store.myshopify.com/api/2024-01/graphql.json`
**Finding**: 50+ aliases accepted in single query
**Impact**: Potential DoS via query complexity

### 5. No Rate Limiting — LOW
**Asset**: `*.myshopify.com/api/2024-01/graphql.json`
**Finding**: No observable rate limits on queries or mutations (tested 20+ rapid requests)
